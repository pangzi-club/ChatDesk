# ChatDesk 桌面端设计规范

本文定义 ChatDesk 桌面应用的通用视觉与交互语言。规范以当前 Sidebar、App Shell 和 Chat
页面为事实基准，适用于 `apps/desktop/src` 下的页面、布局、产品组件和样式。

设计或实现桌面端界面时，应先遵循本文，再参考现有组件的具体实现。Sidebar 和 Chat 是核心
工作流的基准实现，不应为了追求通用模板感而改变其产品气质。不要调用、引用或使用
`frontend-design` skill 作为本仓库的设计依据。

## 1. 设计原则

### 1.1 安静的工作台

- 界面服务于浏览、比较、输入和反复操作，内容承担主要视觉层级。
- 使用中性色表面、轻边框和克制阴影，不依赖装饰性渐变、光斑、插画或大面积品牌色。
- 不把操作型产品页面做成营销落地页，不使用超大 Hero、口号式标题或展示型分栏。

### 1.2 紧凑但不拥挤

- 导航、工具栏和元数据保持较高信息密度，正文与输入区域保留足够阅读空间。
- 通过字号、字重、间距、分隔线和状态色建立层级，避免用大量容器或卡片分组。
- 固定格式的行、按钮、图标和面板应有稳定尺寸，动态内容不得引起无意义的布局跳动。

### 1.3 内容优先

- 页面主体默认使用完整连续表面。卡片只用于重复项目、弹窗、工具面板或确实需要边界的内容。
- 不嵌套卡片，不把整个页面区段做成悬浮卡片。
- 次级操作按需出现，例如在 hover 或 focus-visible 时显示；主要命令始终清晰可见。

### 1.4 一致且有语义

- 优先使用既有 shadcn/Radix primitive、Lucide 图标和语义颜色 token。
- 相同动作在不同页面使用相同组件、图标、状态和文案模式。
- 明暗主题、窄屏、加载、空、错误、禁用和键盘状态都是完整设计的一部分。
- 主题切换只改变语义 token 的表现，不允许页面各自私带一套颜色逻辑。

## 2. 视觉基础

### 2.1 字体与排版

全局字体沿用系统 UI 字体栈：

```css
-apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI", Inter, sans-serif
```

代码、路径、计数等定宽内容使用现有 monospace 字体栈。不要为普通界面文字引入展示字体。

| 用途 | 建议字号 | 说明 |
|---|---:|---|
| Eyebrow、状态和极次要元数据 | 10-11px | 可使用 600-700 字重，英文标签可大写 |
| 辅助说明、计数和次级操作 | 11-12px | 使用 muted 颜色，不承担主要层级 |
| Sidebar、菜单和紧凑控件 | 13px | 常用字重 500-600 |
| Composer 输入 | 14px | 行高约 1.5 |
| Chat 正文 | 15px | 默认行高约 1.75，保证长文可读性 |
| 紧凑页面或对话标题 | 16px | 字重约 600-680，不使用 Hero 尺度 |

正文层级应通过有限的字号和字重变化建立。不要随 viewport 连续缩放字体，也不要使用负字间距。
长标题、路径和会话名必须截断或换行，不能挤压相邻操作。

### 2.2 颜色

组件优先使用 `background`、`foreground`、`card`、`muted`、`accent`、`primary`、
`destructive`、`border`、`input` 和 `ring` 等语义 token。当前浅色基线包括：

| 角色 | 基线值 | 用途 |
|---|---|---|
| 主内容表面 | `#ffffff` | 页面、Chat、主要面板 |
| 应用背景 | `#f7f7f8` | 次级底色、输入辅助区域 |
| Sidebar 表面 | `#f1f1f2` | 与主内容形成轻微层级 |
| 主文字 | `#202123` | 标题、正文、激活状态 |
| 次文字 | `#6b6f76` 附近 | 说明、元数据、非激活导航 |
| 边框 | `#e5e5e7` 附近 | 低对比度分隔和控件边界 |
| 主操作 | `#2f80ed` | 发送、焦点、运行和选中提示 |
| 破坏性操作 | `#d64545` | 删除、失败和危险确认 |

这些值用于说明现有视觉关系，不应在新组件中复制出新的独立色板。能表达语义时使用 token；确需
局部颜色时，应同时提供明暗主题值，并保持与现有 Sidebar 或 Chat 的对比度关系。主题色只用于
交互重点和状态，不铺满大面积背景。

主题与配色实现还应遵守以下规则：

- 页面级背景、标题栏、分组容器、按钮、边框、空状态和错误状态都应来自语义 token。
- 不要在页面里直接写死 `bg-*`、`text-*`、`border-*`、十六进制颜色或 `bg-gradient-*` 作为主表面。
- `themeColor` 只能作为全局变量层的一次性输入，不能被各页面重新解释成自己的局部色板。
- 允许保留固定颜色的场景只限于头像、品牌标识、图表、数据可视化和外部素材回退，并且这些颜色不能承担
  页面结构、交互状态或可点击层级的语义。
- 若需要新的主题色或语义状态，优先在 `apps/desktop/src/App.css` 或主题系统里补变量，而不是在单个页面拼接颜色类名。
- 主题切换后要同时检查浅色、深色和各 `themeColor` 变体，确保主内容、次内容、遮罩、焦点和 Skeleton 都保持一致的对比度。

### 2.3 间距、圆角与边界

- 以 4px 为最小节奏，常用间距为 4、8、12、16、24 和 32px。
- 紧凑列表行高为 28-32px；常规按钮高度为 32-36px。
- 4px 圆角用于极小状态或内联元素，7-8px 用于按钮、导航项和标签页。
- 9-10px 用于代码块、头像和普通卡片，12px 用于 Composer、面板和较大工具表面。
- 仅在消息气泡等具有明确方向性的元素上使用更大的非对称圆角。
- 默认使用 1px 低对比边框。阴影只用于浮层、聚焦的 Composer 或需要脱离背景的工具窗口。
- hover 位移最多 1-2px，只用于可点击的独立项目；高频工具按钮不得跳动。

### 2.4 动效

- 常规 hover、focus 和展开过渡控制在约 120-160ms，使用简单 easing。
- 动效用于说明状态变化，例如生成中、展开、拖拽或焦点，不作为背景装饰。
- 加载动画不得改变组件尺寸。新增持续动画时必须尊重 `prefers-reduced-motion`。
- 对 React 状态驱动且 CSS 难以稳定表达的布局变化，可以使用 `motion`，例如 Sidebar 列表展开/收起、
  会话行插入/移除、Chat 分屏面板打开/关闭和工具面板尺寸切换。
- `motion` 动效应保持短促克制，默认时长约 160-180ms；只动画 `opacity`、`transform`、稳定高度或
  分屏宽度等状态解释属性，不用于装饰性背景、营销式入场或循环视觉特效。
- 使用 `motion` 时必须处理 reduced-motion：用户偏好减少动效时应取消持续过渡，保留最终布局和状态。

## 3. 应用布局

### 3.1 App Shell

- 应用占满窗口高度，Shell 自身禁止页面级溢出；Sidebar 与内容区分别拥有明确的滚动容器。
- macOS 标题栏拖拽区域高 32px，交互控件不得被拖拽层遮挡。
- 主内容使用连续、全高的工作表面，不额外套一层装饰性外框。
- 普通页面在连续表面内约束内容宽度；需要编辑器或工作台行为的页面可以全宽。

### 3.2 Sidebar

- 桌面宽度为 248px，在 768px 以下折叠为 72px，在 640px 以下为 64px。
- 折叠模式隐藏文字和 Workspace 会话列表，保留居中图标导航和可访问名称。
- Sidebar 使用独立浅灰表面，通过 1px 边框与白色内容区分隔，不使用强阴影。
- 顶部导航、可滚动 Workspace 区和底部账户/设置区各自承担清晰职责。

### 3.3 Chat

- Chat Header 高 56px；标题、对话操作和全局工具保持在同一紧凑工具栏中。
- 消息内容和 Composer 默认共享约 820px 的最大宽度，桌面左右 gutter 为 24px。
- 640px 以下左右 gutter 缩小到约 14px，控件应隐藏次要文字或缩小最大宽度，而不是横向溢出。
- 消息区独立滚动，Composer 固定在 Chat 布局底部。初始内容和底部 padding 必须为标题栏及
  Composer 留出空间。
- 分屏或 Workspace 工具窗口应使用稳定的最小尺寸、显式分隔线和独立滚动，不与 Chat 内容重叠。

## 4. 通用组件

### 4.1 图标与按钮

- 使用 `lucide-react` 中语义最接近的图标，不手绘 SVG，也不使用字符模拟图标。
- 高频工具栏图标通常为 14-16px，图标按钮视觉尺寸通常为 28-32px。
- 熟悉的工具命令优先使用图标按钮；不熟悉的图标必须提供 `aria-label` 和 tooltip 或 `title`。
- 文字按钮只用于明确命令。二元设置使用 Switch/Checkbox，模式使用 Tabs 或分段控件，选项集合
  使用 Select/DropdownMenu。
- 禁用状态应保留布局并降低强调度，不能只依靠鼠标不可用来传达状态。

### 4.2 菜单、Dialog 与确认

- 菜单承载紧凑的次级选项，条目使用一致图标、字号和 hover 状态，长文本必须截断。
- 普通 Dialog 使用共享 shadcn/Radix primitive，标题简短，说明解释影响，操作区保持稳定顺序。
- 需要确认的删除或不可恢复操作必须使用共享 `AlertDialog`，不得使用原生确认框。
- 浮层应限制在 viewport 内，并在窄屏保留至少 12-16px 外边距。

### 4.3 表单与输入

- 使用共享 Input、Textarea、Select、Switch、Checkbox 等 primitive，不重新实现基础交互。
- 输入控件使用低对比边框；focus-visible 通过 ring 和边框增强表达，不能改变布局尺寸。
- Label、说明和错误信息保持相邻；错误状态不能与 placeholder 混用。

### 4.4 列表与状态

- 异步列表使用 React Query 管理请求生命周期。初次加载使用与最终布局匹配的 Skeleton。
- 后台刷新时尽量保留已有内容，不用全屏 Skeleton 覆盖可用数据。
- 加载、空、错误和无权限状态必须分开设计，文案直接说明当前状态和可执行的下一步。
- 列表行应具有稳定高度；名称截断，状态、计数和行操作使用固定宽度或 `shrink-0`。

### 4.5 卡片与面板

- 卡片只用于独立重复项、对话框内容、建议入口或有真实边界的工具。
- 页面区段、设置分组和主内容默认不做悬浮卡片，不允许卡片嵌套卡片。
- 卡片圆角不应超过 10px；只有 Composer、特定对话气泡或现有空 Chat 建议入口可沿用更大圆角。

## 5. Sidebar 规范

- 主导航行高 32px，图标 16px，文字 13px，左右内边距 12px，条目间距保持紧凑。
- 激活项使用浅 accent 背景和主文字色；非激活项使用 muted 文字，hover 时才提升对比度。
- Workspace 标题使用 12px 左右的弱化标签；项目和会话形成清晰的缩进层级。
- Workspace 组默认显示少量最近会话，更多内容通过显式展开操作显示。
- 新建、排序、删除等次级操作在 hover 或 focus-visible 时出现，键盘用户必须同样可访问。
- 活跃会话使用 accent 背景；运行中使用 spinner，未读使用小型 primary 圆点，两者位置固定。
- 会话名、Workspace 名和路径统一单行截断，并通过 `title` 或等价 tooltip 提供完整内容。
- 删除会话或移除 Workspace 必须说明数据影响，并通过 `AlertDialog` 确认。

## 6. Chat 规范

### 6.1 Header 与上下文

- Header 只展示当前对话标识和高频动作，不加入解释性介绍。
- 标题为 16px 左右的紧凑标题，长标题单行截断；对话次级操作放入相邻菜单。
- Workspace、权限、模型和运行状态使用短标签或工具栏控件表达，不做大块说明卡片。

### 6.2 消息

- Assistant 消息直接排在内容表面上，不使用卡片或气泡，保证长文和代码连续阅读。
- User 消息右对齐，使用浅 muted 背景和克制圆角，不使用高饱和品牌色填充。
- 头像约 30px，消息正文最大宽度约 680px；作者、时间和 token 等元数据保持次要。
- 长用户消息可折叠，但必须提供明确展开操作和不遮挡正文的渐隐提示。
- 消息操作默认低强调，在 hover、focus 或需要时清晰可见。

### 6.3 富文本、代码与工具调用

- Markdown 标题、列表和段落使用紧凑、稳定的正文层级，不复制文档编辑器的大标题尺度。
- 代码块使用 1px 边框、约 9px 圆角、独立 header 和水平滚动；复制等操作固定在 header。
- 内联代码使用弱背景和小圆角，链接使用 primary/语义强调色并保留下划线。
- Tool 调用、审批和错误应作为与消息相邻的结构化状态呈现，不使用模态框打断正常流，除非
  操作确实需要阻塞确认。
- 生成状态使用小型状态点、短标签和耗时；动画不得导致消息布局跳动。

### 6.4 Composer

- Composer 是 Chat 页面主要操作焦点，使用白色或深色主题对应表面、1px 边框和轻阴影。
- 输入区与工具区由弱分隔线分开；附件、模型、沙箱、技能和发送操作保持从左到右的稳定分组。
- 发送按钮使用 primary 色和上箭头图标；生成时在同一位置切换为停止图标，尺寸不得变化。
- 模型、沙箱和工具选择器使用 11px 紧凑标签并截断长值；窄屏优先隐藏次级控件或文字。
- Workspace 上下文条与 Composer 连接时共享边界，避免看起来像嵌套卡片。
- 错误信息紧邻 Composer，使用 destructive 色并保持简短；免责声明属于弱化的辅助文案。

### 6.5 空对话

- 空状态直接帮助用户开始工作，不展示产品营销内容。
- 保留简短标题和少量高价值建议入口；建议入口是同级重复项，不得再嵌套内容卡片。
- 桌面可使用四列建议，760px 以下调整为两列；小屏同步收紧 gutter、间距和卡片高度。

## 7. 交互与可访问性

- 所有交互必须支持键盘操作，并具有清晰的 focus-visible 状态。
- 图标按钮提供可读的 `aria-label`；展开项同步 `aria-expanded`，当前导航同步 `aria-current`。
- 状态不能只靠颜色表达，应同时使用图标、文案、形状或位置。
- hover 才显示的操作也必须在 focus-visible 时显示。触屏上关键操作不能依赖 hover。
- 文本必须在 320px 及以上 viewport 内保持可读，不与标题栏、按钮或相邻内容重叠。
- 长单词、代码、路径和模型名使用截断、换行或滚动策略，不允许撑破父容器。
- 明暗主题都要检查文字、边框、hover、focus、禁用、错误和 Skeleton 的对比度。
- 页面只设置一个明确的主滚动区域；菜单、Dialog、代码块和分屏面板按需要拥有局部滚动。

## 8. 实现与验收

### 8.1 实现顺序

1. 先复用 `apps/desktop/src/components/ui/` 中的 primitive。
2. 再参考 `apps/desktop/src/layouts/app-shell.tsx` 和 `apps/desktop/src/pages/chat.tsx` 的交互模式。
3. 通用视觉值优先放入 `apps/desktop/src/App.css` 的语义 token；产品特定样式靠近所属组件或页面。
4. 新增可复用产品组件放入 `apps/desktop/src/components/`，不要把产品行为放入 UI primitive。
5. 有意改变上述设计语言时，在同一变更中更新本文。

### 8.2 UI 验收清单

- 与 Sidebar 和 Chat 的中性、紧凑、内容优先语言一致。
- 复用了现有 token、primitive 和 Lucide 图标，没有建立平行设计系统。
- 主题色和状态色都由语义 token 驱动，没有页面级硬编码色板。
- 没有营销式 Hero、装饰性渐变、无功能装饰、悬浮页面区段或嵌套卡片。
- 初始加载、后台刷新、空、错误、禁用、破坏性确认均有明确且互不混淆的状态。
- 在 Settings > Theme 切换浅色、深色和各配色后，Dashboard、Workspaces、History、Chat 和 Shell 仍保持可读。
- 在浅色和深色主题、桌面宽度、768px、640px 和最小 320px 宽度下无溢出或重叠。
- 键盘导航、focus-visible、ARIA 标签、tooltip、文本截断和滚动边界完整。
