本地 AI 工作台 · 三进程 + 一个真相源

ChatDesk 把会话、流式事件、模型适配、工具执行、文件与终端都装进同一个本机进程群。 UI 只负责渲染与发指令；Node HTTP Server 是 Session / Run 的唯一真相源；Tauri 负责拉起 sidecar、注入 token、提供原生能力与沙箱。

Tauri 2 React 19 + Vite 7 Node 22 (--watch + strip-types) Hono 4 AI SDK 7 TypeScript 7

01 顶层视图

单窗口桌面应用由 Tauri 壳、WebView 中的 React UI、以及一个被 Tauri 拉起的 Node Chat Server 组成。 三者通过本机 HTTP / SSE 通信，端口由 Tauri 启动时随机分配并通过 token 鉴权。

02 Monorepo 布局

pnpm workspace 三个包：浏览器壳、Node 服务、共享合约。三条依赖方向：UI → Chat Server 通过 @chatdesk/chat-server-client 边界；两侧共用 @chatdesk/shared；Tauri 是独立原生层，不被其他包直接 import。

// apps/server/package.json { "dependencies": { "@ai-sdk/mcp": "^2", "@ai-sdk/openai": "^4", "@chatdesk/shared": "workspace:*", "@hono/node-server": "^1", "ai": "^7", "hono": "^4", "sharp": "^0.35", "undici": "^7", "zod": "^4" } }

03 Chat HTTP Server：真相源

Hono 应用负责会话持久化、多路并发 Run、SSE 事件流、模型调用编排、工具执行边界。 所有 API 除 /health 与 CORS 预检外都校验 Authorization: Bearer <token>。

关键不变量

1) Server 拥有 Run，不与 React 路由或组件生命周期绑定；
2) 同一 session 串行（重复 start 返回 409），跨 session 必须并行；
3) 状态机至少含 idle · submitted · streaming · error · ready，通过 SSE 下发；
4) 仅绑定 127.0.0.1，随机端口，启动期生成 token，崩溃重启 / SIGTERM 优雅退出。

04 Run 生命周期

RunRegistry 把会话消息流翻译成 streamText 调用，处理工具循环、检查点压缩、 沙箱审批、Plan / Todo / UserInput 等内置工具，并把每一步以 SSE 事件下发。

05 桌面 UI 分层

浏览器壳遵循清晰的依赖方向：pages 拼装、components 复用、lib 收口所有平台调用、shared 只放运行时无关合约。

数据获取 React Query

列表、缓存、refetch 状态都交给 @tanstack/react-query。

  • 首屏加载用 layout-matching skeleton
  • refetch 期间保留旧内容
  • 空 / 错 / 加载三态独立

破坏性操作 AlertDialog

必须使用共享的 shadcn AlertDialog 二次确认。

  • 禁止 window.confirm
  • 删除 / 清空 / 终止都走同一组件
  • 统一文案 + ESC 关闭

设置页搜索 Settings

新增 / 删除 / 重命名 Settings 路由时同步更新搜索项。

  • 每条 label / keyword 都可被搜到
  • 由 settings 自身的 search index 收口

设计语言 Desktop

Sidebar / App Shell / Chat 体验是设计基准，详见 docs/desktop-design-guidelines.md。

  • 安静、紧凑、内容优先
  • 禁止引入并行视觉系统
  • 如修改准则请在同一 PR 中更新文档

06 Tauri 原生层

Rust 侧只做薄命令 + 服务：拉起 sidecar、注入 token、提供 sandbox / 终端 / 文件 / git 原生能力。 业务逻辑留在 Node；前端通过 @/lib/* 中的小适配器调用 invoke。

// apps/tauri/src-tauri/src/lib.rs (节选) .invoke_handler(tauri::generate_handler![ commands::sandbox::get_sandbox_info, commands::sandbox::run_shell_command, commands::sandbox::workspace_list_dir, commands::terminal::terminal_spawn, commands::terminal::terminal_write, commands::chat_server::chat_server_info, commands::chat_server::chat_server_restart, services::user_data::read_user_store, services::user_data::write_user_store, commands::automation::sync_automation_tasks, ])

07 沙箱与权限

Seatbelt（macOS 默认）+ 通用 deny-by-default profile：被允许的写操作集中在工作区根与数据目录； shell 三档 ask / auto / full 由 run-policy + sandbox-boundary-reviewer 决策，结果落到 SandboxReviewLogStore。

08 共享合约层

@chatdesk/shared 只放运行时无关的 TypeScript 类型、Zod schema、常量与算法， 不引用 React / DOM / Node / Tauri / fs。两端 tsc --noEmit 共享同一份类型。

// packages/shared/src/index.ts export * from "./chat.ts"; // ChatSession · ChatIndexItem · RunStartInput · 状态机常量 export * from "./image-generation.ts"; // 模板与生成记录结构 // packages/chat-server-client/src/index.ts export { ChatServerClient, ChatServerError } from "./client.ts"; // fetch + EventSource 封装，跨 WebView / Node 都能用

09 工具链与产物

所有脚本在仓库根目录统一执行；CI 与本地开发共用同一条命令链。

10 数据落盘

CHAT_SERVER_DATA_DIR 在 macOS 默认 ~/.chatdesk/chat-server， 其他平台使用 .data/chat-server。每个 session 自成一个目录，元数据与消息 JSONL 分离。

~/.chatdesk/chat-server/ ├── sessions/<session-id>/ │ ├── meta.json // 标题 / 时间戳 / workspace / 摘要 │ ├── messages.jsonl // 每行一条 UIMessage │ ├── plan-<rand>.md // plan mode 文件 │ └── attachments/ // Sharp 压缩后的图片 ├── settings.json ├── memory.json ├── workspaces.json ├── server-config.json ├── archive/ // 用户归档（codex/claude/cursor/kimi） ├── archive-uploads/ // 临时上传目录 ├── activity-log.jsonl ├── ai-usage-log.jsonl └── image-generation.json
迁移策略

旧版本（session.json、无 cwd 的 Default 会话、.data/ 旧布局） 通过 pnpm migrate <command> --apply 显式迁移，应用不会自动执行。

11 一句话总结

Session / Run 的真相源在本机 Node HTTP Server；UI 只消费 HTTP 与 SSE；Tauri 负责进程与 敏感能力；三层通过 pnpm workspace 与 @chatdesk/shared 的合约共享类型， 用 @chatdesk/chat-server-client 收紧边界。
